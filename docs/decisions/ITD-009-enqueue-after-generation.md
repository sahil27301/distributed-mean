| ITD 9 - _Enqueue a job's items only after all its files exist_ |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **THE PROBLEM**                                                | When do a job's raw files become claimable: all at once after generation, or in batches while generation is still running?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **OPTIONS CONSIDERED (Decision in bold)**                      | _**Generate every file, then flip to `running` and insert all F items in one transaction**_ <br> Pipelined: insert items in batches as files land, so workers merge while the API generates <br> No raw files: leaf tasks regenerate their deterministic inputs in memory                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **REASONING**                                                  | One flip transaction gives a simple, verifiable resume story (design §6.4). Workers never see a half-generated job. The conditional `UPDATE ... WHERE status = 'generating'` enqueues at most once, even with two API instances. Resume only has to skip files that already exist. <br> Pipelining needs an `enqueued_count` on `jobs`, bumped in the same transaction as each batch so a restart knows where to continue. It also needs a status meaning "running but still generating". Completion stays correct, because `files_covered` can only reach F once every file has been enqueued. It is a real latency win at large F, but it rewrites the resume logic. <br> Regenerating in workers removes 400 GB of writes and reads at max size, but it departs from the problem's model of generated files that workers read. It also leaves nothing on disk to check results against. |
| **TRADEOFFS**                                                  | Workers sit idle for the whole generation. At max size that is about 2.8 h of single-threaded CPU in the API (about 100 ms per 1M-value file, measured), plus 400 GB of raw files on disk, before any item exists. <br> Generation runs on Node's event loop, so a large job also slows API responses until it finishes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **NOTES**                                                      | Generation cost is outside the problem's focus (distribution and aggregation), so we keep it simple. Next steps in order of value: a `worker_threads` pool for `generateFile`; a free-disk check on `POST /jobs`; then pipelining (design §12).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
