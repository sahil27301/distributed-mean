| ITD 2 - _Use Postgres as both the queue and the source of truth_ |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :--------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **THE PROBLEM**                                                  | What do we use as the queue that workers pull work from?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **OPTIONS CONSIDERED (Decision in bold)**                        | **_Postgres `items` table claimed with `FOR UPDATE SKIP LOCKED`_** <br> SQS <br> Redis (lists / streams) <br> RabbitMQ                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **REASONING**                                                    | Consuming inputs and producing the output must be one atomic step (ITD 3). That is only possible if the queue and the state live in the same transactional store. <br> Claims are queries, not FIFO pops: "up to 5 items of job X, biggest count first, not leased". Postgres expresses this directly; leases are just columns. <br> The problem already requires a DB, so this removes a component. <br> SQS: "delete these 5 messages and send 1 new one" can't be a single all-or-nothing operation, so a crash in between leaves both inputs and output alive (double count); this forces idempotent outputs, which dynamic grouping makes hard. It also has no grouping by job or ordering by count. <br> Redis: atomic via Lua, but weaker durability and state duplicated between Redis and the DB. RabbitMQ: same transactional gap as SQS. |
| **TRADEOFFS**                                                    | Workers poll for work (can move to `LISTEN/NOTIFY` later). <br> Postgres caps claim throughput (thousands per second), which is ample while tasks take seconds; at larger scale, shard by job (each job lives entirely on one Postgres instance, so transactions stay single-node; workers rotate across shards). <br> The DB is a single point of failure; standard Postgres HA applies.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **NOTES**                                                        | Claim and commit queries are in the design doc. Index choices: partial index on running jobs `(last_claimed_at, created_at)`, and `items (job_id, files_covered DESC)`. <br> A queue table churns: every job inserts and then deletes all its items, so planner statistics often describe an empty table. Queue queries must be correct under any plan. The claim's locking subquery is a `MATERIALIZED` CTE for this reason ([incident 001](../incidents/001-claim-over-fetch.md)).                                                                                                                                                                                                                                                                                                                                                                |
