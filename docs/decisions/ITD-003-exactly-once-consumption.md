| ITD 3 - _Use atomic consume-on-commit so each input is counted exactly once_ |                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **THE PROBLEM**                                                              | How do we guarantee no file is double counted when the same work can run more than once (crashes, lease expiry, retries, backup copies)?                                                                                                                                                                                                                                                                                                                                 |
| **OPTIONS CONSIDERED (Decision in bold)**                                    | **_One transaction deletes all inputs and inserts the output; roll back if any input is missing; no ownership check (first commit wins)_** Same, plus an ownership check (current lease holder wins) Idempotent outputs with deterministic IDs Reject results whose lease has expired                                                                                                                                                                                    |
| **REASONING**                                                                | A row can only be deleted once, so two attempts with overlapping inputs can never both commit. Repeated work becomes harmless regardless of why it repeated. An ownership check makes the original worker lose whenever someone re-claimed any of its inputs, even if it finishes first with a valid result, and it blocks backup copies (the backup never owns the lease). Deterministic IDs break under dynamic grouping (one attempt merges 1–5, another 3–7). Rejecting by elapsed time throws away valid results even when nobody else took the items, races with the commit, and depends on worker/DB clocks agreeing. |
| **TRADEOFFS**                                                                | The losing attempt's work is wasted. A rolled-back attempt leaves an orphan file in storage; each attempt writes to a unique path, and orphans are garbage-collected later. Every commit touches up to 6 rows.                                                                                                                                                                                                                                                           |
| **NOTES**                                                                    | The final merge (`files_covered` = `file_count`) writes the result reference and marks the job `done` in the same transaction, so completion is also atomic. Input files are deleted from storage only after the commit succeeds.                                                                                                                                                                                                                                                            |
