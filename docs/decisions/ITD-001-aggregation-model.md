| ITD 1 - _Use (sum, count) partials merged in a runtime-shaped tree to compute the mean_ |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| :-------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **THE PROBLEM**                                                                         | How do we split a job across workers (≤5 inputs per task) and combine their outputs into a correct mean?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **OPTIONS CONSIDERED (Decision in bold)**                                               | **_Every item is a (sum vector, count); any 2–5 items of a job merge into one; the tree shape emerges at runtime_** <br> Static pre-planned tree (fixed groups per level) <br> Average of averages <br> Split by index (C) <br> One worker streaming all files with a running sum                                                                                                                                                                                                                                                                                                                                                                           |
| **REASONING**                                                                           | A mean is not mergeable, but (sum, count) is: `(S1, n1) + (S2, n2) = (S1+S2, n1+n2)`, mean = `S / n` once at the end. The merge is associative and commutative, so any grouping in any order is valid. No task depends on a specific partial, so a slow worker never blocks a specific merge. <br> A static tree makes each merge wait for specific children, so the slowest child blocks its parent. <br> Average of averages is wrong when groups are uneven (e.g. F=12 → 5, 5, 2). <br> Splitting by index needs all F files per task, which violates the 5-file limit. <br> Streaming in one worker defeats the per-task limit and uses no parallelism. |
| **TRADEOFFS**                                                                           | No fixed task plan, so progress can't be "tasks done / total". Instead: every merge of k items removes k−1 items, so progress = (F − items remaining) / (F − 1). <br> Floating point is not associative; mitigated by using integer values (ITD 8). <br> Every item must carry its count.                                                                                                                                                                                                                                                                                                                                                                   |
| **NOTES**                                                                               | With fan-in 5, total tasks ≈ (F−1)/4, i.e. ~25% merge overhead on top of the first level. Equivalent to FedAvg with every client weighted by its count. <br> Future: also split by column range (each range reduced independently, written to its offset in the result) to add parallelism when F is small and C is large, and to bound per-task cost across jobs. Deferred because it buys nothing at large F: F = 100k already gives about 20k leaf tasks for W workers. Per-task memory is at most about 16 MB (about 100 MB for the final CSV write) even at C = 1M (measured).                                                                        |
